# 오른쪽 패널

## 판이 셋이다 — 세션 · 출근부 · 설정

설정과 출근부는 원래 `<dialog>`였다. 창은 배경 차단과 Esc 닫기를 공짜로 줬지만 420px에
갇혀 방 목록·표가 좁았고, **사무실을 보면서 만질 수 없었다.** 셋 다 패널 판으로 들어왔다 (#115).

- 세 판의 뼈대는 **고정이고 숨겨 둔다**(`#pane-session`·`#pane-att`·`#pane-cfg`).
  갈아 끼우면 안쪽 id가 매번 새로 생겨 그때마다 이벤트를 다시 달아야 한다
- **보이기(`applyPanelTab`)와 내용 다시 그리기(`drawPanelView`)를 갈라 뒀다.** 앞은 스냅샷마다
  불러도 싸지만, 뒤는 판을 다시 짜므로 스크롤 자리와 펼쳐 둔 것이 초기화된다
- **자리를 고르면 세션 판으로 돌아온다.** 설정을 열어 둔 채 자리를 눌렀을 때 아무 반응이
  없으면 고장으로 읽힌다
- **탭이 두 판으로 가는 유일한 문이다.** 상단바에도 출근부·설정 버튼이 있었지만 같은 곳으로
  가는 두 번째 문이라 걷어냈다(#135) — 오른쪽 도구 묶음은 좁은 창에서 먼저 밀리는 자리다.
  그래서 **탭 클릭이 `openAttTab`·`openCfgTab`을 탄다**: 두 판은 열 때 main에서 값을 다시
  받아 와야 하는데(출근부 집계 · 알림 · 단축키 — 스냅샷과 달리 밀려 오지 않는다) 버튼이
  그 길을 쥐고 있었다. `setPanelTab`을 바로 부르면 첫 진입에서 설정 판이 빈 판으로 뜬다
- `setPanelTab`은 **패널이 접혀 있으면 먼저 펴 준다** — 탭은 패널 안에 있어 접혀 있으면
  보이지 않으므로, 이 길로 오는 것은 자리 클릭이다
- 패널은 330px이라 **420px 창보다 좁다.** 방 탭이 넘쳐서(이름이 밖으로 밀려 나가고 세기 칸이
  잘렸다) 이름이 한 줄을 통째로 쓰고 컨트롤 셋이 다음 줄을 나눠 갖게 고쳤다

## 세션 판 — 순서가 곧 위계다

전에는 섹션 제목 일곱아홉 개가 전부 같은 크기·같은 색이어서, 스크롤하는 동안 "나를 기다린다"와
"처음 지시"가 동등하게 지나갔다. 지금은 이 순서로만 읽힌다 (#113):

나를 기다림 → 컨텍스트 → 지금 상황 → 서브에이전트 → 요약 → 계획·할 일 → 지시 → 타임라인

- **대기만 카드이고 나머지는 라벨이다.** 위계를 색이 아니라 형태로 낸다
- 기본 정보 열두 개는 `터미널 · 가동 47분 · 갱신 방금 전` 한 줄로 접었다(`<details>`,
  JS 없이 열린다). 값은 하나도 없애지 않았다 — 늘 보는 것이 셋뿐이라 접은 것이다
- 패널은 두 층이다 — 굴러가는 몸통(`.panel-body`)과 **바닥에 고정된** 주 동작(`.jump`).
  전에는 내용 맨 끝이라 타임라인이 길면 묻혔다
- 맨 아래에 **터미널에서 열기** 버튼과 `claude attach <id>`(터미널 세션은
  `claude --resume <sessionId>`) 복사 버튼이 있다

적지 않기로 한 것이 아니라 얻을 수 없다(엔트리 이름이 경로의 해시다.

## 승인받은 계획

플랜 모드로 승인받은 계획이 있으면 제목 한 줄과 **계획서 열기** 버튼이 뜬다(기본 편집기로 연다).

- 제목은 계획 **본문**에서 뽑는다. 파일이 지워졌어도 트랜스크립트에 본문이 남아 있어 제목은
  나온다 — 그때는 열기 버튼 없이 제목만 적는다
- 눌렀는데 파일이 사라졌으면 버튼 아래에 그렇게 적는다. 눌렀는데 아무 일도 안 일어나는 것이
  가장 나쁘다
- 대화가 아주 바쁘면 승인 줄이 트랜스크립트 꼬리 밖으로 밀려나 안 보일 수 있다
  ([무엇을 읽는가](data-sources.md#승인받은-계획-scanplan) 참고)

## 할 일 목록

세션이 스스로 할 일을 세웠으면(`~/.claude/tasks/`) `할 일 2/6`과 진행 막대,
그리고 **아직 안 끝난 항목**이 뜬다. 끝낸 것은 머릿수로 접는다 — 열여덟 줄이 그대로 쌓이면
아래 블록을 밀어내고, 이 자리는 "지금 무엇을 하는지"가 보여야 하는 곳이다.

- 또렷한 한 줄이 **진행 중인 항목**이다. 나머지는 다 가라앉혀 둔다
- 순서를 기다리는 항목에는 `#3 끝나야 시작`이 붙는다(점선 네모). **빨강으로 칠하지 않는다** —
  이 앱에서 빨강은 실패·위험이고 차례가 아닌 항목은 잘못된 게 아니다
- 진행 막대는 컨텍스트 막대와 달리 문턱 색이 없다. 많이 찬 것이 좋은 것이라서
  60·85%에서 노랑·빨강으로 물들면 안 된다
- **할 일을 안 쓴 세션에는 이 블록이 아예 안 뜬다.** 실측상 그게 대부분이다
  ([무엇을 읽는가](data-sources.md#세션이-세운-할-일-maintasksmjs) 참고)

진행 중인 항목의 `activeForm`은 **말풍선에도 실려 나간다** — 우리가 요약한 상황보다
그 세션이 직접 쓴 문장이 정확하다. 흰 말풍선(세션 기반)이다.

## 터미널에서 열기

발견한 세션의 작업 디렉터리에서 attach 명령을 실행하는 **터미널 창을 띄운다.**
Windows는 Windows Terminal이 있으면 **이미 열려 있는 창에 새 탭**으로 붙이고(`wt -w 0 nt`),
없으면 conhost로 떨어진다. 맥은 Terminal.app에 새 창을 띄운다(`osascript`).
어느 쪽이든 셸을 띄우고 그 안에서 명령을 돌린다 — `claude`를 바로 실행하면 세션이 끝나는 순간
창이 닫혀 무슨 일이 있었는지 볼 수 없다.

못 띄우면(터미널을 못 찾거나 지원하지 않는 플랫폼) **명령을 클립보드에 넣고** 이유를 버튼 아래에 적는다.

- 앱에서 세션에 **답을 대신 밀어넣지는 않는다.** 남의 터미널 stdin을 건드리는 일이고,
  창을 띄우는 것까지가 상한이다. 기다리는 세션에 `state.json`의 추천 답이 있으면
  **추천 답 복사** 버튼이 붙는데, 그것도 클립보드까지다 — 붙여넣기는 사람이 한다
- 렌더러가 만든 **명령 문자열은 main으로 넘기지 않는다.** 잡 id·세션 id만 넘기고 명령은
  `main/terminal.mjs`가 조립한다 — 렌더러에서 온 문자열을 셸에 넘기면 그게 곧
  임의 명령 실행 통로가 된다. id는 `[A-Za-z0-9._-]`만 받는다
- 작업 디렉터리가 사라졌으면 홈에서 연다. 명령 자체는 어디서든 돌기 때문이다

같은 일을 **창을 열지 않고도** 할 수 있다. 트레이 메뉴 **기다리는 세션**에 지금 답을 기다리는
것들이 오래 기다린 순으로 뜨고(최대 8개), 누르면 그 세션의 터미널이 바로 열린다.
전역 단축키 `Ctrl+Alt+W`는 그 목록의 첫 번째를 연다 — [설정](settings.md#단축키) 참고.
트레이 메뉴에 적는 이름은 **이름 가리기 설정을 따른다**(가리면 방 이름을 쓴다) — 화면을
공유하는 동안엔 트레이 메뉴도 같이 보이기 때문이다. OS 알림도 같은 규칙으로 돈다
([설정](settings.md#이름을-가리면-알림도-가린다)).

**아무것도 선택하지 않았을 때**는 현재 시각과 계정 상태가 기본 화면이다.

- 큰 시계 + 날짜 (1초마다 갱신)
- 출근 인원 · 작업 중 · 입력 대기 · 최고 컨텍스트 · 붙어 있는 서브에이전트 수
  (+ [예비 슬롯](data-sources.md#빈-예비-슬롯은-출근시키지-않는다)이 있으면 그 개수와 설명)
- **세션(5시간)·주간(7일) 사용률** 프로그레스 바 + 초기화 시각 + 남은 시간
- 최근 12시간 내 퇴근한 작업
- **읽고 있는 곳** — 앱이 읽는 `~/.claude` 경로
- 맨 아래 한 줄에 앱 버전 (Electron 버전은 쓰는 사람에게 뜻이 없어 적지 않는다)

## 계정 값과 세션 값을 섞지 않는다

모델 · 컨텍스트 창 · 추론 강도 · Fast는 **계정 단위가 아니다.** `office-usage.json`은
[statusline이 떨어뜨린 payload](#사용량은-왜-tap이-필요한가)이고, 그건 **그 statusline을 그린
세션**의 값이다. 세션마다 다를 수 있으므로 기본 화면(계정)에 적으면 그게 곧 오해가 된다.

그래서 이 값들은 **세션 패널에** 있다.

- 모델·컨텍스트 창은 대화 파일에서 읽은 그 세션의 값(`w.model`·`context.limit`)이 우선이다
- 그게 없으면(첫 턴 전이라 대화 파일이 비었으면) payload의 `session_id`가 **그 세션과 같을 때만**
  payload 값을 쓴다
- 추론 강도·Fast는 대화 파일에 없다 — **payload의 세션과 일치하는 자리에만** 적고,
  모르는 세션에는 아예 칸을 만들지 않는다

계정 사용량 블록에는 진짜 계정 단위인 것만 남는다 (세션 5시간 · 주간 7일).

## 도움말은 접어 둔다

말풍선 두 종류를 읽는 법과 "자리를 클릭하면…" 힌트는 **한 번 읽으면 되는 안내**라
기본 화면 자리를 계속 차지할 이유가 없다. 우측 하단 **물음표 버튼**을 누르면 캡션처럼 떠오르고,
바깥을 누르거나 Esc로 닫힌다. 내용이 고정이라 `renderer/index.html`에 그대로 두고
`app.mjs`는 여닫기만 한다.

## 폰트

**사무실(캔버스) 안의 글자만 픽셀 폰트를 쓴다.** 상단바와 오른쪽 패널은 Pretendard 그대로다.
[Mona](https://github.com/MonadABXY/mona-font)의 획을 편 변형 **Mona S** 12px 한글 텍스트판을
`renderer/fonts/MonaS12TextKR.woff2`로 넣어 뒀다 (SIL OFL 1.1, `renderer/fonts/OFL.txt`).
한글 완성형 11,172자 + Basic Latin 100% 커버.

- 시스템에 `MonaS12`가 설치돼 있으면 `src: local('MonaS12')`이 먼저 걸려 그쪽을 쓴다
- 둘 다 없으면 `Galmuri11` → `Malgun Gothic` → `monospace` 순으로 조용히 내려간다
- 비트맵 폰트는 한 크기에서만 또렷하므로 확대 배율과 무관하게 **12px 고정**으로 그린다
  (`OFFICE_FONT`·`OFFICE_FONT_PX`). 굵기도 400 하나만 쓴다 — 볼드 페이스가 없으면 브라우저가
  합성 볼드로 픽셀을 번지게 하므로, 방 이름 강조는 색으로 한다
- 글자 원점을 정수로 반올림해 그린다. `textAlign: center`에 맡기면 0.5px이 남아
  서브픽셀 안티에일리어싱이 껴서 픽셀 폰트가 흐려진다
- **캔버스는 DOM 텍스트가 아니라서 `@font-face` 선언만으로는 폰트가 로드되지 않는다.**
  `app.mjs`가 `document.fonts.load('12px MonaS12')`로 직접 불러온 뒤 글자 폭 캐시를 비운다

말풍선 크기는 글자 폭을 실측해서 잡으므로 어느 폰트로 떨어져도 레이아웃이 깨지지 않는다.

## 사용량은 왜 tap이 필요한가

세션·주간 사용률은 Claude Code가 **statusline 스크립트의 stdin으로만** 넘겨준다. `~/.claude` 어디에도
파일로 남지 않고 CLI에도 꺼낼 명령이 없다. 그래서 statusline이 받은 payload를 그대로
`~/.claude/office-usage.json`에 떨어뜨리게 해두고 앱은 그 파일만 읽는다.

심고 빼는 입구는 두 개인데 하는 일은 같다 (`main/usage-tap.mjs` 하나를 공유한다).

- **트레이 아이콘 > 사용량 연동 (statusline)** — 설치본에서 쓰는 길. 체크하면 심고, 끄면 뺀다
- 레포에서 바로 돌릴 때는 CLI도 있다

```powershell
npm run usage-tap          # statusline 스크립트에 심기 (.bak 백업을 남긴다)
npm run usage-tap:remove   # 빼기
```

`settings.json`의 `statusLine.command`에서 `.ps1` 경로를 찾아 **stdin을 읽는 줄 앞뒤로** 두
블록을 넣는다. 각각 마커(`# >>> claude-office … >>>`)로 감싸 두어 여러 번 실행해도 한 번만 심기고,
실패해도 statusline 자체는 그대로 돈다. PowerShell 5.1이 한글 주석을 cp949로 읽지 않도록
저장할 때 BOM을 붙인다.

| 위치 | 하는 일 |
|---|---|
| 읽는 줄 **앞** | `[Console]::InputEncoding`을 UTF-8로 맞춘다 (아래 참고) |
| 읽는 줄 **뒤** | payload를 `office-usage.json`에 그대로 쓴다 |

파일 맨 앞에 넣지 않는 이유는 PowerShell의 `param()`이 **첫 실행문이어야 하기 때문이다** —
그 앞에 문장을 끼우면 스크립트가 깨진다. stdin 읽기는 언제나 `param()` 뒤에 있다.

### stdin 인코딩을 왜 맞추나

PowerShell 5.1은 `[Console]::In`을 `[Console]::InputEncoding`으로 읽고, **Korean Windows
기본값이 cp949다.** payload에 한글이 있으면 — 세션 이름은 첫 지시에서 나오므로 한국어로 쓰면
거의 항상 있다 — **그 자리에서 글자가 깨진다.** 매핑 못한 바이트가 `?`로 대체되므로 뒤에서
UTF-8로 다시 써도 복구되지 않고, JSON이 부서져 사용량이 아예 안 읽힌다.

```
…"effort":{"level":"high"},"session_name":"異붽??좊쭔??湲곕뒫 寃??,"model":{…
```

실제로 이렇게 닫는 따옴표까지 사라져 뒤가 통째로 못 읽혔다. 머리말 한 줄이 그걸 막고,
statusline 자신의 한글 출력도 같이 고쳐 준다.

**예전 버전이 심어둔 tap에는 이 머리말이 없다.** 앱을 켤 때 알아보고 조용히 보태고
(`.bak`은 남는다) 알림으로 알려준다. 파일을 계속 못 읽는 동안에는 패널이 마지막으로 읽힌
값이라고 밝힌다 — 옛 숫자를 현재값처럼 보여주면 그게 거짓말이 된다.

**자동 설치는 statusline이 PowerShell(.ps1)일 때만 된다.** bash 등 다른 statusline이면 —
맥은 항상 이 경우다 — 직접 넣을 수 있는 코드를 알려준다(트레이는 대화상자로, CLI는 표준출력으로).
안내에는 bash용 한 줄(`printf '%s' "$payload" > …/office-usage.json`)도 들어 있어,
stdin을 읽은 뒤에 그대로 넣으면 똑같이 동작한다.
tap이 없으면 그 칸에 안내만 뜨고 나머지 기능은 전부 그대로 동작한다.
