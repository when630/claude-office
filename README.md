# claude-office

로컬에서 돌아가는 Claude Code 세션들을 픽셀 사무실로 보여주는 트레이 상주 앱.
작업 디렉터리 하나 = 사무실 한 칸, 세션 하나 = 그 방에서 일하는 클로드 한 마리.
일하는 동안엔 자리에 앉아 타이핑하고, 일이 없으면 자리에서 일어나 방을 돌아다니며
혼잣말을 하고 가끔 옆자리와 잡담을 한다.

```powershell
npm install       # 아이콘은 postinstall이 굽는다
npm start         # 개발 실행
npm run usage-tap # 세션·주간 사용률을 앱이 읽게 statusline에 한 줄 심는다 (선택)
npm run build     # dist/ 에 설치본(NSIS) 생성
```

Electron 43 · 런타임 의존성 없음.

## 트레이 상주

- 창을 닫아도 종료되지 않고 트레이로 내려간다. 진짜 종료는 **트레이 아이콘 > 종료**
- 트레이 아이콘이 상태를 물고 있다 — 평소엔 클로드, **입력 대기가 생기면 노란 점**, 실패가 있으면 빨간 점.
  마우스를 올리면 `5명 출근 · 3 작업 중 · 1 입력 대기`
- 입력 대기 세션이 새로 생기면 **Windows 토스트**가 뜬다. 누르면 창이 열리며 그 자리가 선택된다.
  앱을 막 켠 순간 이미 대기 중이던 것들은 알리지 않는다(시끄러우므로)
- 트레이 메뉴에서 알림 on/off와 **로그인 시 자동 시작**을 켤 수 있다. 자동 시작은 `--hidden`으로 붙어
  창 없이 트레이에만 올라온다
- **사용량 연동 (statusline)** 체크박스가 statusline tap을 심고 뺀다 ([아래](#사용량은-왜-tap이-필요한가)).
  설치본에는 npm도 `tools/`도 들어가지 않으므로 여기가 유일한 입구다. 자동으로 못 붙이면
  손으로 넣을 안내를 대화상자로 띄운다
- 설정은 `%APPDATA%\claude-office\settings.json` — 트레이 메뉴의 값과 상단바 **설정** 버튼([아래](#설정))의
  값이 같은 파일에 들어간다

## 무엇을 읽는가

`claude agents`가 쓰는 것과 같은 파일들을 main 프로세스에서 직접 읽는다. CLI를 스폰하지 않아 가볍고,
1.5초마다 스냅샷을 떠서 **바뀐 경우에만** 렌더러로 보낸다.

비교할 때는 스냅샷을 뜬 시각(`ts`)을 뺀 서명을 쓴다(`signature`). 그걸 그대로 비교하면 매 틱 값이
달라져 차단이 아무 일도 하지 않고, 아무 일이 없는데도 1.5초마다 IPC와 패널 재생성이 돌아
**패널 스크롤 위치와 텍스트 선택이 계속 풀린다.** 같은 이유로 경과 시간은 상대값이 아니라
절대 시각(`statusAt`)으로 넘긴다 — 상대값이면 여기서 아무리 걸러도 매 틱 달라진다.
유휴 세션만 있는 동안 이 서명은 실측상 완전히 고정된다.

| 소스 | 쓰임 |
|---|---|
| `~/.claude/sessions/<pid>.json` | 살아있는 세션 목록 — 이름·cwd·kind·`jobId`, 그리고 `status`(`busy` / [`waiting`](#선택지가-뜨면-산책하지-않는다) / `idle`) |
| `~/.claude/jobs/<id>/state.json` | 백그라운드 잡의 detail·`needs`·토큰·연결된 MR |
| `~/.claude/jobs/<id>/timeline.jsonl` | 상태 전이 이력 (마지막 12건) — 백그라운드 잡만 |
| `~/.claude/projects/<cwd>/<sessionId>.jsonl` | **모든 세션**의 제목·최근 지시·진행 요약·MR·컨텍스트 사용량·타임라인 |
| `~/.claude/office-usage.json` | 계정 사용량 — statusline이 떨어뜨려 준 payload (아래 참고) |

`process.kill(pid, 0)`으로 살아있는 프로세스만 남기므로, 죽은 세션 파일이 남아 있어도 출근시키지 않는다.
`CLAUDE_CONFIG_DIR`을 설정해 뒀다면 그쪽을 따라간다.

### 빈 예비 슬롯은 출근시키지 않는다

Claude Code 데몬은 백그라운드 세션을 빨리 띄우려고 프로세스를 **미리 데워 둔다**(`daemon/roster.json`의
`source: "spare"`). 이 슬롯도 `sessions/<pid>.json`을 만들기 때문에 그대로 그리면 **프롬프트를 한 번도
받지 않은 빈 프로세스가 정직원처럼 자리에 앉는다** — 출근 인원이 부풀고, 이름도 `8e4edbee` 같은 짧은
id로 떠서 정체를 알 수 없다(name도 intent도 없어 id가 그대로 이름이 된다).

그래서 `collect.mjs`의 `isSpare`가 이런 세션을 사무실에서 빼고, 개수만 `stats.spare`로 넘겨
패널의 **예비 슬롯** 칸에 적는다 — 숨기기만 하면 "있는데 안 보이는 것"이 되므로.

판정은 일부러 빡빡하다. `kind: bg`이고 status가 idle이며 잡 상세·제목·최근 지시·intent·토큰·
컨텍스트·서브에이전트·타임라인이 **전부 비어 있을 때만** 예비로 본다.
터미널 세션은 아예 대상이 아니다 — 갓 띄운 창도 기록이 없지만 그건 곧 사람이 쓸 자리다.

### 터미널 세션도 상세가 나오는 이유

백그라운드 잡은 `state.json`에 detail·needs를 남기지만 **터미널 세션(`kind: interactive`)은 그런 파일이 없다.**
그래서 예전에는 터미널 세션 카드가 이름·PID만 있는 빈 껍데기였다. 지금은 트랜스크립트에서 직접 캐낸다:

| 트랜스크립트 줄 | 쓰임 |
|---|---|
| `{"type":"ai-title","aiTitle":…}` | 세션 제목 (카드 부제) |
| `{"type":"last-prompt","lastPrompt":…}` | **최근 지시** |
| `{"type":"system","subtype":"away_summary",…}` | **지금 상황** (1순위) |
| 마지막 `assistant` 메시지의 텍스트 | **지금 상황** (2순위 — away_summary가 없을 때) |
| `{"type":"pr-link",…}` | 연결된 MR |
| `{"type":"mode","mode":…}` | 현재 모드 |
| 마지막 `assistant`의 `usage` | **컨텍스트 사용량** (`input + cache_creation + cache_read`) · **토큰** |
| `async_launched` 뒤에 완료 알림이 안 온 `agentId` | **지금 돌고 있는 서브에이전트** (옆에 비서가 선다) |
| `timestamp`가 붙은 `user`·`assistant` 줄 | **타임라인** (아래 참고) |

**타임라인은 출처가 두 개다.** 백그라운드 잡은 `timeline.jsonl`에 상태가 바뀔 때마다 요약을
한 줄씩 남겨 주므로 그게 있으면 그걸 쓴다(초록 점 = `done`). 터미널 세션은 그런 파일이 없어
대화에서 턴을 주워 쓴다 — **받은 지시(노란 점) ↔ 한 말(파란 점)** 을 시간순으로 최대 8칸.

턴을 줍는 데는 함정이 둘 있다.

- `last-prompt` 줄에는 **timestamp가 없고** 매 턴 같은 내용이 다시 쓰인다 — 턴 경계로 못 쓴다.
  시각이 붙어 있는 `user`/`assistant` 줄을 쓴다
- `user` 줄에는 사용자가 친 게 아닌 것이 섞여 온다. 도구 결과(`tool_use_id`)는 턴이 아니면서
  줄이 제일 크므로 **JSON 파싱 전에** 문자열로 걸러내고, 슬래시 명령은 `<command-name>` 블록을
  `/이름 인자`로 펴고, 캐비어트·시스템 리마인더는 버린다(`isMeta`가 안 붙어 오는 경우가 있다)

한 턴이 길면 320KB 안에 사용자 지시가 아예 없을 수도 있다(도구 결과가 꽉 채운다). 그때는
`assistant` 쪽 턴만으로 채워지는데, 그래도 "무슨 말을 하며 진행했는지"는 순서대로 보인다.

대화 파일이 수십 MB까지 자라므로 뒤쪽 320KB만 읽고, 크기·mtime이 그대로면 캐시를 재사용한다.
마크다운(표·코드블록·굵게)은 한 줄 텍스트로 눌러 편다. 서브에이전트(`isSidechain`) 사용량은
부모 세션 컨텍스트가 아니므로 세지 않는다.

컨텍스트 퍼센트 계산은 Claude Code statusline이 쓰는 것과 같다. 모델별 창 크기는
`main/transcript.mjs`의 `CONTEXT_LIMITS` — 지금은 haiku만 200K이고 나머지 현행 모델은 1M이다.

## 사무실 종류

방마다 종류가 배정돼 벽·바닥 무늬·책상 색·비품이 달라진다. 같은 화면에 같은 종류가 몰리지 않게
해시로 고르되 이미 쓴 종류는 옆으로 밀어준다. 방 이름 오른쪽에 `개발실 · 3`처럼 표시된다.
마음에 안 들면 [설정](#설정)에서 방마다 종류를 골라 못 박을 수 있다.

| 종류 | 자리 | 바닥 | 놓인 것 |
|---|---|---|---|
| 개발실 | 책상 + 모니터 | 격자 | 정수기 · 서버 랙 · 화분 · 쓰레기통 |
| 디자인실 | 제도판 (선이 자란다) | 나무 | 화분 · 스탠드 · 선인장 · 서류함 |
| 라운지 | 낮은 테이블 + 노트북 (쿠션에 앉는다) | 나무 | 커피머신 · 소파 · 자판기 · 화분 · 오락기 |
| 회의실 | 회의 테이블 하나에 **마주 앉는다** (아래 참고) | 카펫 | 정수기 · 화분 · 박스 (+ 벽에 프로젝터 스크린) |
| 연구실 | 흰 실험대 + 플라스크 (거품이 오른다) | 타일 | 비커 · 어항 · 서류함 · 소화기 |
| 자료실 | 칸막이 열람석 + 펼친 책 + 스탠드 | 타일 | 책장 · 서류함 · 박스 · 스탠드 |
| 서버실 | 금속 콘솔 + 모니터 2대 + 상태 LED | 타일 | 서버 랙 ×2 · 선풍기 · 소화기 |
| 운영실 | 책상 + 모니터 | 격자 | 프린터 · 정수기 · 서류함 · 쓰레기통 |

**일하는 모습도 자리에 따라 다르다.** 개발실·운영실은 키보드를 두드리고, 회의실은 손짓을 하고,
연구실은 두 팔을 든 채 플라스크를 젓고, 자료실은 책장을 넘기고, 디자인실은 도면에 선을 긋고,
서버실은 LED가 바쁘게 깜빡인다. 작업 중이 아니면 그 움직임이 전부 멈춘다.

벽에는 시계·액자·창문이 걸리고, 방 종류별 대사도 따로 있다(회의실에서는 "스크린이 안 켜진다").
책상 위에는 세션마다 다른 잡동사니(머그·간식·포스트잇·서류·전화기·캔·헤드셋)가 놓인다.
비품은 좌·우 벽에서 안으로 쌓이고 가운데는 비워둔다 — 거기가 다들 모이는 자리다.

### 회의실만 배치가 다르다

다른 방은 벽에 붙은 책상 줄이지만, 회의실은 **테이블 하나를 놓고 인원을 반씩 갈라 마주 앉힌다.**
테이블 하나가 한 블록이고, 인원이 열 명을 넘으면 블록이 하나 더 생긴다.

그리는 순서가 곧 앞뒤 관계다 — 먼 쪽 → 밀어 넣은 빈 의자 → 상판 → 명패 → 자료 → 가까운 쪽.

- **먼 쪽**은 상판이 하반신을 가려 앉은 것처럼 보인다. 이름표를 바닥에 두면 마주 앉은 줄이 밟으므로
  상판 위 **명패**로 올린다(카드 폭은 글자를 실측해서 맞춘다). 컨텍스트 게이지는 명패 아래에 깔린다
- **가까운 쪽**은 등받이가 뷰어 쪽이라 캐릭터보다 **나중에** 그려 하반신을 덮는다. 상판이 하던 일을
  등받이가 대신하는 셈이고, 이게 없으면 테이블 앞에 서 있는 것처럼 보인다. 팔걸이가 몸통 옆으로
  삐져나와야 앉은 자세로 읽힌다. 자료·머그는 머리 위(상판 앞쪽)에 놓인다
- 자리를 비우면 먼 쪽은 **명패를 접어 눕히고**, 가까운 쪽은 의자를 상판 아래로 밀어 넣는다

## 캐릭터가 하는 짓

### 어떻게 생겼나

Claude Code 마스코트(Clawd)를 16×12 픽셀로 옮겼다. `shared/pixels.mjs` 맨 위에 규칙 셋이 있다.

- **위는 평평하다.** 좌우로 튀어나온 두 덩어리는 팔이다. 처음엔 그걸 몸통 위로 올려 그렸는데
  팔이 아니라 머리에 난 뿔로 읽혔다 — 위로 세우지 말고 옆으로 낸다
- **팔은 눈과 같은 높이다.** 몸통은 12px, 팔이 좌우로 2px씩 삐져나와 그 줄만 16px이 된다.
  아래로 내리면 팔이 아니라 옆구리로 읽힌다
- **음영이 없다.** 하이라이트도 그늘도 없는 단색 한 겹이다. 위 모서리에 밝은 줄을 한 줄 넣어
  봤는데 몸의 굴곡이 아니라 머리띠로 보였다. 어두운 바닥 위에서는 실루엣만으로 충분하다
- **다리는 네 짝 두께가 같다.** 2px씩 네 개, 가운데 틈만 두 배로 벌려 앞다리·뒷다리를 가른다.
  틈을 다 같게 두면 네발짐승이 아니라 스툴 다리로 보인다

그래서 자세 차이는 전부 **실루엣**으로만 낸다 — 팔 높이(`stand`·`armsUp`·`armsHigh`),
발 들림(`stepA`·`stepB`), 눈 모양. 눈은 흰자 없는 검은 사각 2×2이고, 그 **아랫줄만** 남기면
감은 눈, **윗줄만** 남기면 웃는 눈이다 — 이 크기에서 둘을 가르는 유일한 수단이다.
떠들 때는 레퍼런스의 웃는 얼굴(`> <`)로 바꾼다.

앉으면 상판이 하반신을 덮어 다리가 안 보인다(그래야 앉은 것처럼 보인다). 그래서 타이핑은
다리가 아니라 **팔을 한 줄 올렸다 내리는** 것으로 만든다 — 팔은 눈 높이라 상판 위에 늘 남는다.

걷기는 네발짐승답게 **대각선 짝**으로 딛는다(왼쪽 바깥 + 오른쪽 안쪽 ↔ 그 반대). 안쪽 짝 /
바깥 짝으로 갈랐더니 네 발이 한꺼번에 같은 방향으로 움직여 걷는 게 아니라 깡충 뛰는 모습이었다.
그리고 걸을 때 몸통을 1px 띄우던 것을 걷어냈다 — 띄우는 박자가 걷기 프레임과 같아서 발을 든
1px과 정확히 상쇄되고, 딛는 발이 두 프레임 내내 같은 높이에 붙어 있었다.

| 상태 | 판정 | 모습 |
|---|---|---|
| 작업 중 | `status === 'busy'` | 자리에 앉아 팔을 놀려 키보드를 두드리고, 모니터에 코드가 흐른다 |
| 입력 대기 | `status === 'waiting'` 또는 `state.json`의 `needs` | 자리에서 일어나 제 책상 앞을 서성이며 두 팔을 든다 · ❗ |
| 완료 | `state` = `done` | 바닥을 돌아다닌다 · ✓ |
| 실패 · 정지 | `state` = `failed` / `stopped` | 의자에 늘어져 있다 · ✗ / zZ (정지는 반투명) |
| 대기 | 그 외 | 자리를 비우고 방을 어슬렁거린다 |

### 자리와 바닥 사이 — 순간이동하지 않는다

mood만 보고 그리면 일이 끝난 순간 게가 책상에서 사라져 바닥 아무 데나 나타나고, 일이 시작되면
반대로 순간이동한다. 그래서 전환을 넣었다.

| 단계 | 시간 | 모습 |
|---|---|---|
| 일이 끝났다 | 0 ~ 1.5초 | 자리 앞에 나와 서서 ✓ + "다 했다!" |
| | ~ 3.1초 | 그 표시를 그대로 든 채 바닥으로 걸어 나간다 |
| | 이후 | 평소 산책 |
| 일이 시작됐다 | 0 ~ 1.6초 | ✱ + "받았습니다"를 띄우고 자리 앞까지 걸어온다 |
| | 이후 | 자리에 앉아 타이핑 |

- 나가는 목표 지점을 **원래 산책 경로(`walkPos`)로 잡는다.** 그래서 전환이 끝나는 순간 경로에
  정확히 얹힌다. 들어올 때는 반대 방향으로 같은 보간을 쓴다
- 전환 중인 놈은 **잡담 짝에서 뺀다** — 다 했다는 표시를 들고 걸어 나가는 길에 붙잡혀 서면 안 된다
- 입력 대기는 ✓ 없이 곧바로 자리 앞으로 나온다 — 거기서 ❗를 들고 선다. 실패·정지도 걸어와 앉지만
  ✱는 띄우지 않는다(축하할 일이 아니다)
- 자리 앞에 서는 지점은 **슬롯 폭을 줄 수로 나눈 균일 격자**다. `seatCx`만 쓰면 두 줄인 방의
  같은 열과 회의실의 마주 앉은 짝이 한 점에 겹치고, 고정 폭 오프셋으로 벌리면 다른 열·다른 줄
  조합이 4px 차이로 떨어져 이름표가 덧찍혔다. 격자면 어디서나 간격이 `52/줄수`로 같다
  (2줄 26px · 3줄 17px · 4줄 13px — 4줄은 11인 이상 회의실 전원이 동시에 끝날 때만 3px 스친다)
- 늘어선 동안에는 **이름표를 x 순위 홀짝으로 두 줄에 나눠** 적고(이웃과 항상 다른 줄),
  상태 기호(✓ 등)도 옆이 아니라 **제 머리 위 가운데**로 올린다 — 옆(cx+12)에 붙이면 옆 게의
  몸을 덮는다. 13px 폭이라 격자 간격 안에 든다
- 정지 상태는 **걸어오는 동안에도 앉은 몸과 같은 투명도**로 흐리다 — 아니면 또렷한 몸으로
  걸어와 앉는 순간 톤이 툭 바뀐다

#### 여기서만 위치를 기억한다

이 앱은 걷는 경로를 시간에서 유도해 상태를 들고 있지 않는데, **전환만 예외로 워커별 마지막 위치를
기억한다**(`anchors`). 계산만으로는 "지금 어디에 있는지"를 몰라서 세 가지가 튀었다 — 실측 최대 210px:

- 앉아 있던 게가 다시 일하면(실패 후 재시도) 바닥으로 순간이동한 뒤 걸어 돌아왔다
- 전환이 끝나기 전에 상태가 또 바뀌면 새 전환의 반대쪽 끝으로 스냅했다
- 스냅샷이 1.5초 늦게 오면 그만큼 진행된 지점에서 시작해 **걷기의 절반이 점프로 대체**됐다

그래서 진행도의 기준도 `statusAt`이 아니라 **렌더러가 그 상태를 처음 본 시각**이다. `statusAt`은
경과 시간 표시에만 쓰고, 전환은 **mood가 바뀐 것만** 본다 — 잡 상태에서 오는 `failed`/`stopped`처럼
`statusAt`이 갱신되지 않는 전이도 놓치지 않는다. 단계가 넘어갈 때는 출발점만 다시 잡는다
(hold → out에서 자리 앞부터 출발해야 모서리를 자르지 않는다).

고친 뒤 프레임 간 최대 이동량은 **0.6px**이다(전이 10종 · 16ms 스텝 시뮬레이션).

앉아 있는 동안에도 앵커를 **매 프레임 현재 자리 앞으로 갱신**한다 — 안 하면 창 크기가 바뀌어
방이 옮겨진 뒤 일어날 때 옛 좌표(책상 줄 안쪽까지 70px 어긋난 지점)에서 출발한다. 전환 도중의
리사이즈는 출발점을 바닥 안으로 잡아두는 것으로 막는다.

대가는 둘이다. 렌더러를 새로 열면 앵커가 비어 그 순간엔 전환 없이 제자리에 나타난다(앱을 켠
직후와 같아서 오히려 낫다 — 모두가 한꺼번에 걸어 들어오지 않는다). 그리고 **`statusAt`을 조작해
단계를 강제할 수 없다** — 디버그로 전환을 보려면 `__office.push`로 mood를 실제로 바꿔야 한다.

### 선택지가 뜨면 산책하지 않는다

권한 확인·선택지(AskUserQuestion)·플랜 승인처럼 **답을 기다리는 동안** Claude Code는
`sessions/<pid>.json`의 `status`를 `waiting`으로 바꿔 준다. 이걸 안 보면 `idle`로 떨어져
게가 자리에서 일어나 방을 어슬렁거리고, 정작 나를 부르고 있다는 신호가 아무 데도 안 뜬다.

- **트랜스크립트로는 알 수 없다.** 실측해 보면 선택지가 떠 있는 동안 대화 파일에는 아무것도
  안 쓰인다 — 답한 뒤에야 `tool_use` 줄이 붙는다. 세션 파일의 `status`가 유일한 단서다
- **프롬프트 앞에서 그냥 쉬는 것은 `idle`이다.** 두 시간 넘게 방치된 세션도 `idle`로 남으므로,
  `waiting`은 "정말로 내 답에 막혀 있는 상태"만 가리킨다 — 끝난 세션마다 알림이 울리지 않는다
- 백그라운드 잡은 `state.json`에 **무엇을** 기다리는지(`needs`)까지 남기지만 터미널 세션은 그게
  없다. 그래서 말풍선은 대기 상투구("허락 한 번만 주세요")와 마지막 상황을 번갈아 띄우고,
  패널에는 "터미널에 선택지나 확인이 떠 있습니다"를 적는다
- 기다리는 놈은 **잡담 짝에서 빼둔다.** 짝이 잡히면 느낌표가 접히고 대사가 잡담으로 바뀌어,
  정작 불러야 할 때 옆자리와 수다를 떠는 꼴이 된다

여기에 트레이 아이콘 노란 점과 Windows 토스트가 함께 붙는다(트레이 메뉴에서 알림을 끌 수 있다).

**얼마나 기다렸는지**도 세 곳에 적는다. `statusAt`(status가 바뀐 절대 시각)을 스냅샷에 실어
보내므로, 렌더러가 1초마다 직접 세면 되고 스냅샷이 늦게 와도 시간이 어긋나지 않는다.

| 어디 | 무엇 | 갱신 |
|---|---|---|
| 상단바 | `3 입력 대기 · 최장 2시간 5분` — 가장 오래 방치된 놈 | 스냅샷마다 (1.5초) |
| 말풍선 | `3분째 기다리는 중…` — 무엇을 기다리는지 · 얼마나 · 재촉을 번갈아 | 대사 주기마다 |
| 패널 | `2시간 5분째 기다리고 있습니다` — 초까지 | 1초 (패널을 다시 그리지 않고 이 줄만) |

**1분 안쪽은 시간을 적지 않는다.** "0분째"는 정보가 아니라 소음이고, 금방 답할 프롬프트까지
재촉하는 꼴이 된다(패널만 예외로 초 단위를 보여준다 — 거기까지 갔다면 이미 보고 있는 것이다).

방은 벽에 붙은 **자리 줄**(회의실은 테이블)과 그 아래 **빈 바닥**으로 나뉜다. 앉아 있지 않은 쪽은 바닥을 걸어 다니는데,
같은 방 인원수만큼 구역을 나눠 갖기 때문에 한곳에 뭉치지 않는다. 걷는 경로는 시간만으로 정해져
(상태를 들고 있지 않아) 창을 다시 그려도 같은 자리에 있다. 자리를 뜨면 의자는 책상 밑으로 밀려 있다.

**세 구간마다 한 번은 다 같이 러그 위로 모인다.** 구간 경계는 모두가 공유하고 도착 시각만 하나씩
흩어 놓았으므로, 줄줄이 행진하지 않으면서도 같은 순간에 멈춰 선다. 절반쯤은 머그를 들고 있다.

**잡담**은 그때 벌어진다. 같은 방에서 둘 다 멈춰 서 있고 26px 안으로 가까우면 한 쌍으로 묶여
질문–대답을 주고받는다(`빌드 됐어?` → `아직 도는 중`). 누가 먼저 말하는지는 키 순서로 고정돼
프레임마다 뒤바뀌지 않고, 대화 내용도 시간·키 해시로만 정해져 상태를 따로 들고 있지 않다.

**혼잣말**은 8초에 한 번 4.8초쯤 떴다 사라진다. `state.json`이나 트랜스크립트에 실제 내용이 있으면
그것과 상투구를 번갈아 말한다 — 말풍선만 봐도 무슨 일을 하는지 대충 읽힌다. 일하는 중이 아니면
방 종류·시간대에 맞는 말도 섞는다(새벽엔 "이 시간의 나를 믿지 마라").

### 말풍선 색이 두 가지인 이유

같은 모양이면 지금 뜬 말이 **실제 상황인지 그냥 분위기인지** 구분이 안 된다. 그래서 색을 갈랐다.

| | 색 | 내용 |
|---|---|---|
| **세션 기반** | 흰 말풍선 + 왼쪽 파란 띠 | `state.json`의 detail·needs, 트랜스크립트의 최근 지시·제목, 서브에이전트가 받은 지시 |
| **랜덤 대사** | 어두운 말풍선 | 상태별 상투구, 시간대·방 종류 대사, 서로 주고받는 잡담 |

`speechFor`·`reportFor`가 문장을 고를 때 `kind: 'real' | 'idle'`을 같이 실어 보내고,
`render.mjs`의 `BUBBLE_STYLE`이 그걸로 색을 고른다. 비서 보고는 `{label}`·`{kind}`·`{n}`처럼
**실제로 읽어온 값이 치환된 문장만** 세션 기반으로 센다 — "결과 나오면 바로 알려드립니다"처럼
우리가 써 둔 문장만인 경우는 어두운 말풍선이다. 오른쪽 기본 화면 맨 아래에 이 구분을 적어 뒀다.

### 비서 (서브에이전트)

서브에이전트가 돌고 있으면 **자리 옆에 비서가 서서 진행 상황을 보고한다.** 작은 놈(18×11 —
몸통 12 + 팔 1px씩 + 결재판 4)이 책상 앞에 서고, 본인은 그동안 입을 다문다 — 둘이 동시에
떠들면 말풍선이 겹친다.

비서는 **본체를 그대로 줄인 모습**이어야 한다. 처음에는 몸통을 평평한 8px 사각으로 두고
클립보드를 든 오른팔만 냈는데, 실제 크기로 부모 옆에 세워 보면 다른 생물로 읽혔다 —
팔이 안 삐져나와 실루엣이 직사각형이고, 8px 몸통에 2px 눈이 붙어 얼굴 비율이 무너지고,
1px 다리가 가느다란 선으로 보였다. 그래서 팔·눈·다리를 [본체 규칙](#어떻게-생겼나)대로 되돌렸다.

- **다리는 네 짝을 지킨다.** 다리 수는 실루엣에서 바로 세어지는 것이라 세 짝으로 줄이면
  그것만으로 다른 생물이 된다. 2px 네 짝은 12px이 필요하니 몸통을 본체와 같은 12px로 키우고
  다리 줄을 본체에서 그대로 가져왔다. 작아 보이게 하는 몫은 **키(11줄)와 짧은 팔(1px)**이 맡는다
- **비서가 든 것은 낱장 서류가 아니라 결재판이다.** 흰 종이 뭉치를 매달아 봤더니 세 가지가 걸렸다 —
  팔은 눈높이인데 종이는 그 아래라 **손에서 떨어져 보이고**, 보고 프레임에서 팔만 올라가
  **손을 따라 움직이지 않고**, 어두운 방에서 흰 덩어리가 게보다 먼저 눈에 들어온다.
  가슴 가운데를 채워 "안고 있는" 모습으로도 해봤지만 그건 서류가 아니라 **입(이빨)**로 읽혔다
- 그래서 **테두리 있는 판 + 안에 종이 + 위에 클립**으로 바꿨다. 어두운 테두리가 배경과 물건을
  갈라 주니 흰 덩어리로 번지지 않고, 판 자체가 물건의 경계를 갖는다. 판은 **팔과 같은 줄에서
  시작해** 팔이 판 테두리를 붙잡고, 보고 프레임에서 **팔과 함께 한 줄 올라간다** — 이게
  "들고 있다"를 만드는 전부다. 클립은 윗줄을 좁히고 밝은 금속색을 써서 실루엣만으로 읽힌다
  (글줄은 이 크기에서 글자가 아니라 **파인 홈**이 되므로 넣지 않는다)
- 비서 간격은 **스프라이트 폭에서 끌어온다**(`AIDE_GAP`). 숫자를 박아두면 스프라이트를 키울 때마다
  둘이 겹친다 — 실제로 폭을 10→17로 올렸을 때 5px 겹쳤다(지금은 18). 그림자는 폭만으로 구할 수
  없어(결재판이 오른쪽으로 삐져나온다) 스프라이트 안의 몸통 칸을 `AIDE_BODY_X`·`AIDE_BODY_W`로
  적어 둔다
- 비서가 서는 **높이(`DY_DESK.aide`)는 위아래로 1px씩밖에 여유가 없다.** 자리 모양마다 책상 다리
  아래끝이 달라(책상·서버실·연구실·자료실 +33, 제도판 +34, 낮은 테이블 +30) 그보다 위면 다리 끝이
  발 아래로 삐져나와 **다리를 밟고 선 것처럼** 보이고, 이름표 글자 윗변(+34)보다 아래면 이름표가
  둘째 비서 몸통에 겹쳐 찍힌다. 그래서 정확히 +34다
- 서는 **x(`AIDE_X`)는 옆자리를 밟지 않는 가장 오른쪽**이다. 52면 몸통이 +44~+55에 서고 옆자리
  책상은 +56에서 시작한다. 제 책상(+4~+48)까지 비키려면 +57이 필요해 반드시 옆자리를 침범하므로,
  책상 오른쪽 5px과는 그대로 겹친다(자기 책상 앞이니 맞다)

붙어 있는 서브에이전트를 찾는 곳은 두 군데다.

- 백그라운드 잡: `state.json`의 `fan[]`(데몬이 실시간으로 갱신) → `inFlight.tasks`(개수만)
- 터미널 세션: 트랜스크립트에서 **agentId마다 마지막 사건**을 본다 (`scanAides`)

`fan[]`은 **끝나도 항목이 빠지지 않고 `doneAt`만 붙는다** — 안 걸러내면 유령이 서 있는다.
또 종류를 `agent`로 뭉뚱그리므로, 양쪽 다 들고 있는 `agentId`로 맞춰 트랜스크립트가 아는
`subagent_type`을 붙여 준다.

**"결과가 안 온 `Agent` 호출"로 찾으면 안 된다.** 요즘 `Agent` 도구는 비동기로 띄우고 곧바로
결과를 돌려주기 때문이다 — 6분을 도는 에이전트도 tool_result는 2~3초 만에 온다. 그래서 예전에는
에이전트가 도는 내내 비서가 안 보였다. 지금은 세 가지 줄을 본다.

| 줄 | 뜻 |
|---|---|
| `toolUseResult.status: "async_launched"` (+ `agentId`·`description`) | 띄웠다 |
| `origin.kind: "task-notification"` 의 `<task-id>` | 끝났다 |
| `SendMessage` tool_use 의 `input.to` | 멈춘 놈에게 다시 시켰다 = 또 돈다 |

뒤에서 앞으로 훑으니 **처음 만난 사건이 그 에이전트의 마지막 사건**이다. 띄움·재개면 세우고,
알림이면 세우지 않는다. 알림 없이 3시간이 지난 호출은 세션이 중간에 죽은 흔적으로 보고 버린다
(`AIDE_MAX_AGE_MS`). 결과를 끝까지 기다리는 옛 방식 호출도 그대로 함께 찾는다.

주워 담는 일은 **본문 파싱 루프와 따로** 돈다. 그 루프는 필요한 걸 다 주우면 도중에 멈추는데,
에이전트를 띄운 줄은 몇 분 전 것이라 그 전에 잘려 나가기 때문이다. 같은 이유로 대화가 아주
바쁘면 띄운 줄이 뒤쪽 320KB(`TAIL_BYTES`) 밖으로 밀려나 비서가 사라질 수는 있다.

받은 지시(`description`)와 종류(`subagent_type`)를 그대로 읽어 `설정 로딩 경로 찾기 — 아직 돌고
있습니다`처럼 말한다. `subagent_type`은 알림 줄에 없으므로 띄울 때의 `Agent` tool_use에서
tool_use id로 이어 붙인다. 화면에는 둘까지만 세우고 둘 이상이면 `보조 2명 붙었습니다`처럼 머릿수로 알린다(최대 `MAX_AIDES`=4).

좁은 방에서 여러 마리가 동시에 긴 말을 하면 말풍선이 서로 덮어 아무것도 읽히지 않는다. 그래서
**비서 보고 → 잡담 → 혼잣말** 순으로 놓고, 이미 놓인 말풍선과 겹치는 것은 그 차례를 접는다.
순서가 프레임마다 같으므로 깜빡이지 않는다.

이름표 아래 얇은 막대는 **컨텍스트 사용률**이다. 60% 넘으면 노랑, 85% 넘으면 빨강.

## 오른쪽 패널

캐릭터(또는 그 자리)를 클릭하면 그 세션의 컨텍스트 게이지·붙어 있는 서브에이전트·지금 상황·최근 지시·
연결된 MR·타임라인이 뜨고,
맨 아래 `claude attach <id>`(터미널 세션은 `claude --resume <sessionId>`) 복사 버튼이 있다.

**아무것도 선택하지 않았을 때**는 현재 시각과 계정 상태가 기본 화면이다.

- 큰 시계 + 날짜 (1초마다 갱신)
- 출근 인원 · 작업 중 · 입력 대기 · 최고 컨텍스트 · 붙어 있는 서브에이전트 수
  (+ [예비 슬롯](#빈-예비-슬롯은-출근시키지-않는다)이 있으면 그 개수와 설명)
- **세션(5시간)·주간(7일) 사용률** 프로그레스 바 + 초기화 시각 + 남은 시간
- 모델 · 컨텍스트 창 크기 · 추론 강도 · Fast 모드
- 앱/Electron 버전과 읽고 있는 `~/.claude` 경로
- 최근 12시간 내 퇴근한 작업

### 폰트

**사무실(캔버스) 안의 글자만 픽셀 폰트를 쓴다.** 상단바와 오른쪽 패널은 Pretendard 그대로다.
[Mona](https://github.com/MonadABXY/mona-font)의 획을 편 변형 **Mona S** 12px 한글 텍스트판을
`renderer/fonts/MonaS12TextKR.woff2`로 넣어 뒀다 (SIL OFL 1.1, `renderer/fonts/OFL.txt`).
한글 완성형 11,172자 + Basic Latin 100% 커버.

- 시스템에 `MonaS12`가 설치돼 있으면 `src: local('MonaS12')`이 먼저 걸려 그쪽을 쓴다
- 둘 다 없으면 `Galmuri11` → `Malgun Gothic` → `monospace` 순으로 조용히 내려간다
- 비트맵 폰트는 한 크기에서만 또렷하므로 확대 배율과 무관하게 **12px 고정**으로 그린다
  (`OFFICE_FONT`·`OFFICE_FONT_PX`). 굵기도 400 하나만 쓴다 — 볼드 페이스가 없으면 브라우저가
  합성 볼드로 픽셀을 번지게 하므로, 방 이름 강조는 색으로 한다
- 글자 원점을 정수로 반올림해 그린다. `textAlign: center`에 맡기면 0.5px이 남아
  서브픽셀 안티에일리어싱이 껴서 픽셀 폰트가 흐려진다
- **캔버스는 DOM 텍스트가 아니라서 `@font-face` 선언만으로는 폰트가 로드되지 않는다.**
  `app.mjs`가 `document.fonts.load('12px MonaS12')`로 직접 불러온 뒤 글자 폭 캐시를 비운다

말풍선 크기는 글자 폭을 실측해서 잡으므로 어느 폰트로 떨어져도 레이아웃이 깨지지 않는다.

### 사용량은 왜 tap이 필요한가

세션·주간 사용률은 Claude Code가 **statusline 스크립트의 stdin으로만** 넘겨준다. `~/.claude` 어디에도
파일로 남지 않고 CLI에도 꺼낼 명령이 없다. 그래서 statusline이 받은 payload를 그대로
`~/.claude/office-usage.json`에 떨어뜨리게 해두고 앱은 그 파일만 읽는다.

심고 빼는 입구는 두 개인데 하는 일은 같다 (`main/usage-tap.mjs` 하나를 공유한다).

- **트레이 아이콘 > 사용량 연동 (statusline)** — 설치본에서 쓰는 길. 체크하면 심고, 끄면 뺀다
- 레포에서 바로 돌릴 때는 CLI도 있다

```powershell
npm run usage-tap          # statusline 스크립트에 심기 (.bak 백업을 남긴다)
npm run usage-tap:remove   # 빼기
```

`settings.json`의 `statusLine.command`에서 `.ps1` 경로를 찾아 stdin을 읽는 줄 바로 뒤에
네 줄짜리 `try { … } catch { }` 블록을 넣는다. 실패해도 statusline 자체는 그대로 돌고,
`# >>> claude-office usage tap >>>` 마커로 감싸 두어 여러 번 실행해도 한 번만 심긴다.
PowerShell 5.1이 한글 주석을 cp949로 읽지 않도록 저장할 때 BOM을 붙인다.
자동으로 못 찾으면 직접 넣을 수 있는 코드를 알려준다(트레이는 대화상자로, CLI는 표준출력으로).
tap이 없으면 그 칸에 안내만 뜨고 나머지 기능은 전부 그대로 동작한다.

## 설정

상단바 오른쪽 **설정** 버튼. 고른 값은 `%APPDATA%\claude-office\settings.json`의 `view`에 남아
앱을 다시 켜도 그대로다.

**클로드 이름** — 이름표에 무엇을 쓸지 고른다. 세션 이름은 작업 디렉터리나 첫 지시에서 나오므로
화면을 남에게 보일 때 가려야 할 수 있다.

| 값 | 이름표 | 패널 제목 |
|---|---|---|
| 이름 그대로 | `claude-office` | `claude-office` |
| 가리기 | `클로드 1` | `클로드 1` |
| 이름표 없음 | (없음) | `클로드 1` |

- 대체 이름은 **스냅샷 순서대로 붙인 번호**다. 캔버스와 패널이 같은 이름을 부르므로 누구를 눌렀는지는
  그대로 알 수 있다. 이름표를 없앤 경우에도 패널 제목은 대체 이름으로 남는다 — 제목이 비면
  무엇을 열었는지 알 수 없다
- 이름을 숨겨도 **컨텍스트 게이지는 남는다.** 그건 이름표가 아니라 상태 표시이고, 자리 높이도
  이름이 있을 때와 같게 유지해 방 크기가 흔들리지 않는다
- 회의실 **명패는 접어 눕힌다** — 빈 카드를 세워두면 명패가 고장 난 것처럼 보인다
  (자리를 비웠을 때와 같은 모습)
- 가려지는 건 **이름표뿐이다.** 방 이름(작업 디렉터리)과 패널의 `cwd`는 그대로 남는다

**방 종류** — 지금 떠 있는 방마다 `자동`(해시 배정) + 8종 중에서 고른다. 손으로 고른 종류는 자동
배정보다 먼저 못 박고 "이미 쓴 종류"로 세므로, 남은 방들이 그 종류를 피해 간다. 기억하는 열쇠는
**작업 디렉터리 이름**이라 방이 사라졌다 다시 떠도 고른 종류가 붙어 있다.

`renderer/themes.mjs`에 종류를 하나 추가하면 이 목록에도 자동으로 뜬다.

## 구조

```
main/index.mjs      앱 수명주기 · 창 · 트레이 · 알림 · 폴링 · 설정(settings.json)
main/paths.mjs      ~/.claude 위치 (서로 import하지 않게 여기로 뺐다)
main/collect.mjs    세션·잡·트랜스크립트·사용량 → 스냅샷 한 장
main/transcript.mjs 대화 파일 꼬리에서 제목·상황·MR·컨텍스트·비서 캐내기
main/usage.mjs      office-usage.json → 5시간·주간 사용률
main/usage-tap.mjs  statusline에 사용량 tap 심기/빼기 (트레이·CLI 공용 로직)
main/preload.cjs    contextBridge (샌드박스라 CJS여야 한다)
renderer/           픽셀 렌더러 (app · render · sprites · themes · talk · style)
renderer/fonts/     사무실 영역 픽셀 폰트 (Mona S 12px, OFL 1.1)
shared/pixels.mjs   픽셀 데이터 — 렌더러와 아이콘 생성기가 공유
tools/make-icons.mjs        캐릭터 픽셀 → PNG (의존성 없이 직접 인코딩)
tools/install-usage-tap.mjs 위 로직의 CLI 껍데기 (npm run usage-tap)
```

손댈 만한 곳:

- `shared/pixels.mjs` — 한 글자가 한 픽셀, 팔레트는 파일 맨 위. 행 길이가 어긋나면 바로 에러가 난다
- `renderer/themes.mjs` — 사무실 종류(설정 창의 목록도 여기서 나온다). `station`이 자리 모양을,
  `props`·`wall`이 비품을 정한다
  (둘 다 `renderer/sprites.mjs`의 `SPR` 키 — 회의실 벽의 `screen`만 예외로 `drawScreen()`이 직접 그린다). 자리 모양을 새로 만들려면 `render.mjs`의
  `drawSurface`·`drawGear`·`clawdSeated`에 분기를 추가한다
- `renderer/talk.mjs` — 혼잣말(`LINES`), 시간대 대사(`TIME_LINES`), 잡담(`DUOS`), 비서 보고(`AIDE_LINES`),
  주기(`CYCLE`·`SHOW`). 문장을 고를 때 `kind`를 실어 보내면 말풍선 색이 그에 따라 갈린다
- `renderer/render.mjs` — 방 크기(`SLOT_W`·`SLOT_H`·`FLOOR_BASE`), 자리 배치(`DY_DESK` 주석에 y좌표 정리 · 그리는 곳은 `drawSurface`·`drawGear`·`clawdSeated`),
  돌아다니는 범위·속도(`bandBounds`·`SEG_MS`), 모이는 주기(`HANG_EVERY`), 잡담 거리(`CHAT_NEAR_X`),
  말풍선 색(`BUBBLE_STYLE`), 방 색상 `HUES`
- `main/collect.mjs` — `moodOf`(상태 판정), `RECENT_DONE_MS`(퇴근 목록 유지 기간),
  `isSpare`(빈 예비 슬롯 판정)
- `main/transcript.mjs` — `TAIL_BYTES`(읽는 꼬리 길이), `CONTEXT_LIMITS`(모델별 컨텍스트 창),
  `scanAides`(비서 찾기)·`AIDE_MAX_AGE_MS`(알림 없이 남은 호출을 유령으로 볼 기준)
- `main/index.mjs` — `POLL_MS`, `signature`(스냅샷 중복 전송 판정에서 뺄 필드)

DevTools 콘솔에서 `__office.push(state)` / `__office.select(key)`로 임의 상태를 밀어넣어
입력 대기·실패처럼 평소 안 나오는 화면을 확인할 수 있다. `__office.view({ names, roomThemes })`는
설정을 **저장하지 않고** 바꿔 보는 입구다 — 헤드리스로 화면을 굽어 확인할 때 쓴다.

## 한계

- **로컬 전용**이다. `claude.ai/code`(웹)나 데스크톱 앱에서 돌린 세션은 이 파일들에 남지 않아 보이지 않는다
- 읽기 전용 — 여기서 세션에 답장하거나 정지시킬 수는 없다. 대기 중인 놈을 발견하면 터미널로 가야 한다
- 계정 사용량은 statusline tap에 의존한다. Claude Code 세션에서 statusline이 한 번 그려져야 값이 생기고,
  30분 넘게 갱신이 없으면 "오래됨"으로 표시한다
- 창이 가려져 있거나 다른 가상 데스크톱에 있으면 Chromium이 `requestAnimationFrame`을 멈춘다 —
  캔버스가 안 그려지는 게 정상이고, 창을 다시 보이게 하면 이어서 움직인다
- `~/.claude` 구조는 Claude Code 내부 규약이라 버전이 오르면 바뀔 수 있다 (확인 시점: v2.1.220)
- 빌드본은 코드 서명이 없어 SmartScreen 경고가 날 수 있다 (`추가 정보 > 실행`)
